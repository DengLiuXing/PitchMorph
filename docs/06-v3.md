## 1. 已定下的约束

| # | 约束 | 依据 |
|---|---|---|
| 1 | **导出层不做平滑**（`smooth = 1`），平滑交给 OpenUtau / DAW | D17：3 帧中值滤波就把相邻帧差抹掉 26%，9 帧抹 83%，不可逆 |

## 2. 验收手段要先于模型（V2 真正的瓶颈）——已有 vocadito 基线

V2 的指标原本都是「和 OpenUtau 的 GAME 输出比」，等于用同一模型的后代做尺子。
2026-10-30 引入 **vocadito**（40 段独唱、人工标注音符、每首两个标注者）后，第一次有了绝对口径：

```powershell
uv run python scripts/eval_vocadito.py                       # 全量 40 首，medium + 默认参数
uv run python scripts/eval_vocadito.py --seg 0.1 --est 0.15   # 换参数重测（约 60 s）
```

**基线（40 首均值）**：

| | 音符数 | 起音召回 | 起音精确 | F1 | 音高一致 |
|---|---|---|---|---|---|
| GAME medium（默认参数） | 48 | 74.1% | 81.4% | 0.776 | 82.6% |
| 人类 A2 vs A1 | 47 | 80.1% | 90.1% | **0.848** | 87.7% |

**模型内部旋钮基本无收益**（est 0.1–0.2、seg 0.10–0.20、半径 0.01–0.02、nsteps 8/16、t0 0/0.1/0.25、
medium/large 共 13 组）：F1 全落在 0.771–0.782，只有 large 明显更差（0.771）。

**但切片参数是例外，而且有效**——切片阈值决定每段喂给模型的上下文，之前从没扫过：

| 切片阈值 | 音符数 | 起音召回 | 起音精确 | F1 | 音高一致 |
|---|---|---|---|---|---|
| −30 dB | 41 | 64.0% | 81.9% | 0.652 | 68.6% |
| −40 dB（现行默认） | 48 | 74.1% | 81.4% | 0.776 | 82.6% |
| −50 dB | 48 | 75.0% | 81.6% | 0.782 | 83.8% |
| −60 dB | 48 | 74.7% | 82.1% | 0.781 | 84.6% |
| **−70 dB** | 48 | **75.2%** | **82.5%** | **0.787** | **84.9%** |
| −70 dB + seg 0.15 | 49 | 75.7% | 81.0% | 0.782 | 84.8% |

结论修正：**`-40` 切得太碎，`-70` 让音高 +2.3 点、F1 +1.1 点**，仍差人类天花板 6 个点。
`-30` 会直接把长音切断（音高掉到 68.6%），说明这个参数不是「越小越好」，是「别把连续音切碎」。

**上生产前必须先解决内存**：阈值越宽 → 切片越长 → segmenter 的 O(T²) 越危险
（188 s 整段实测要 5.6 GB）。要做的是「−60 dB + 单片最大长度上限（如 30 s）」，
而不是直接放开阈值。

**切片长度的风险（上生产的前提）**：阈值越宽切片越长，而 segmenter 注意力是 O(T²)。
188 s 素材实测：`-40` 最长片 45.8 s、`-60` 51.2 s、`-70` 62.0 s；整段 188 s 不切时会要 5.6 GB 直接 OOM。
**连续演唱的长歌在任何阈值下都可能出现超长片**，所以除了阈值，单片长度必须有硬上限。

**已在 V2 落地（2026-10-30）**：`config.GAME_SLICE_THRESHOLD_DB = -60`、`GAME_MAX_SLICE_SEC = 30`，
worker 里用 `_CappedSlicer` 包住上游 Slicer，超长片在**能量最低处**再切（固定时长切会把长音劈开）。
两边数据集上的取舍：

| 切片阈值 | vocadito（人类标注，F1 / 音高） | 科学MIMI（GAME 参考，召回 / 精确 / 音高） |
|---|---|---|
| −40（上游默认） | 0.776 / 82.6% | 98.7% / 97.8% / 97.1% |
| −50 | 0.782 / 83.8% | 98.7% / 97.9% / 96.5% |
| **−60（现默认）** | 0.781 / **84.6%** | 97.7% / 98.3% / 96.9% |
| −70 | **0.787 / 84.9%** | 98.8% / 98.3% / 96.4% |

歌曲级参考上四个阈值都在噪声内（96.4–97.1%），人类标注上宽切片一致更好 → 取 −60。
不取 −70 是因为收益只剩 +0.3 点，而切片长度进一步变长、OOM 风险更高。

**试过但不成立的方向**：

| 尝试 | 结果 |
|---|---|
| `t0` 0.1 / 0.25 | 47 音符、F1 与 t0=0 无差异（边界最终收敛） |
| `nsteps` 16 | F1 0.778，与 8 没有区别，白花一倍时间 |
| `large` 体积 | F1 0.771，人工标注上同样更差 |
| **谱通量起音融合**（把 `onset.json` 的峰插进 GAME 音符内部） | z=2.0：召回 75.2→77.7%，但精确 82.5→71.3%，**F1 0.784→0.740**；z=3.5 → 0.772；z=5.0 → 0.781，全不如不融合 |

融合失败的原因值得记住：谱通量峰落在**辅音**上，比人类标注的音符起点（元音起振）早 10–30 ms，
而且同一音符内常有多个能量峰。要能用，得要求「能量谷 + 音高重新起振」同时成立，
那是新算法，不是加个开关。

剩余未试：
- **多种子集成**：D3PM 每次采样不同，跑两次取交集可能提精确率（代价 2× 时间）。
- **帧级 F0 标注**（vocadito 的 `Annotations/F0`）能把「音高错」与「边界错」分开，现在两者混在一个指标里。
- **固定 30 s 分块 vs 静音切片**：既解决 OOM，也能验证「上下文更长更好」这个假设是否被分块破坏。

## 3. 待重构项（按痛感排序）

1. **导出参数散落**：`smooth` 在 `schemas.ExportParams`，`bpm=120` 写死在 `render_export` 默认值，
   曲线密度在 `domain/ustx.py` 的 `DENSITY_SEC`，`PITD_MAX_DEVIATION` 又是另一个常量。
   → 收敛成一个 `ExportSettings`，由创建参数带下来。
2. **`features/` 目录语义膨胀**：`pitch.json` / `onset.json` / `notes.json`（导出输出）/ `notes_game.json`
   四个文件，谁是输入谁是输出只能看代码。→ 引入 `features/index.json` 或严格的 `inputs/` 与 `derived/` 分层。
3. **前端 `App.vue` 三合一**：轮询、视图切换、任务创建都在一个文件里，
   拆成 `composables/useJobs`（轮询 + 列表）与 `useCreateJob`（弹窗 + 参数）。
4. **参数校验两头各写一遍**：pydantic 模型在 `app/schemas.py`，表单在 `CreateJobDialog.vue`，
   默认值与取值范围重复。→ 由 `/api/params/schema` 输出，前端据此生成。
5. **旧格式兼容代码该删**：`config.scope_from_meta` 里的 `_LEGACY_MODE_TO_SCOPE`、
   `Job.mode` 的残留判断，等 `data/jobs` 清空后一并移除。
6. **`orchestrator` 的进度 band 是手写常量**（0.05/0.67/0.73/0.13…），加阶段就得重排。
   → 把每个 stage 的权重写进配置，按存在与否归一化。
7. **缺集成测试**：`pytest` 只覆盖纯函数与 API 形状，`orchestrator` 的真实调度没有测试，
   因为素材不能进 CI。→ 造 1 s 的合成 wav fixture，跑一次「只分析」全链路。
8. **依赖分层**：torch/lightning 都在主环境，但 GAME 只在子进程用。
   → 若走 ONNX（D16 已否决，可复议），主进程这一侧能彻底瘦下来。

## 4. 迁移策略

- V2 的 `data/jobs` 不建议迁移：`meta.json` 已是 v2 格式（`scope` + `params`），V3 若改结构就按新目录重来，
  旧任务只读保留 7 天由 TTL 清掉。
- 权重（620 MB）与 `temp-dev/` 都是本地资产，不入库；V3 换模型时先看 `docs/05-game.md` 的实测表，
  别再从零试体积。
- ONNX 验证脚本在 `temp-dev/onnxcheck/`（未入库）。若要复用，记得 `PATH` 要加 `torch/lib`。
