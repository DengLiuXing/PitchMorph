规则：做分轨、显存或性能验证时先用 `samples/物凄.m4s`（12 s）；要顺带验证容器解码就用 `samples/《花骨朵》亚细亚旷世奇才_洛天依_哔哩哔哩_bilibili.mp4`（170 s）。只有验证「长跑是否累积显存 / 是否随时间退化」才用整曲 `samples/1333699443-1-30280.m4s`（398.8 s，69 个分块），并在结论里注明用的是整曲。

**Why:** 改动（批调度、取消、进度、CUDA 选项）在 12 s 素材上就能看出对错，而整曲 GPU 单轮要 50 s 以上、quality 档还要先付 16 s 的模型重建。用户 2026-10-28 明确要求换成更短的素材加快迭代，并提过要「找短素材再测」全曲并发。

**How to apply:** `scripts/bench.py`、临时诊断脚本与文档里的示例命令默认写短样本；短样本只证明「改动生效」，不能当 steady-state 吞吐——首次 CUDA 图编译（8 s 素材首测 3.78 s/块）和 CPU boost 峰值（短基准 1.21 s vs 长跑 1.72 s）都会把数字带偏。
