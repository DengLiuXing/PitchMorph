2026-10-30：**V2 冻结**（`dev` 分支已推送，132 项测试通过）。用户判断「V2 到瓶颈」，准备 V3 重构。

**Why:** 在 OpenUtau 里看导出的音高线「过于平整」。实测（同一任务 5933 个有声帧，相邻帧差中位数）：
不平滑 6.27 音分 → 3 帧 4.62（−26%）→ 5 帧 2.74（−56%）→ 9 帧 1.06（−83%）。叠加导出侧
`DENSITY_SEC = 0.05`（50 ms 一个控制点），颤音一个周期只剩 3–4 个点，被直线连起来就是「平」。

**How to apply:**
- V3 开发初期**导出不做任何中值平滑**（`smooth = 1`），平滑交给 OpenUtau 自带工具；
  USTX 曲线密度 50 ms → 25 ms（≈ `UCurve.interval` 的 5 tick）。平滑不可逆，数据层不做。
- 决策与代价已写进 `docs/01-decisions.md` D14–D17，重构清单在 `docs/06-v3.md`。
- **V2 真正的瓶颈不是模型，是验收手段**：所有指标都是「和 GAME 输出比」，等价于用同一模型的后代做尺子；
  `est_threshold` 从 0.2 扫到 0.6 全曲指标都在噪声内，D3PM 同参数跑三次能出三种结果。
  V3 第一件事应是建人工标注集（十几首、多唱法、音符级起止+音高），不要先换模型。
- 不要再在 V2 上加功能；`data/jobs` 旧任务不迁移，交给 TTL 清掉。
